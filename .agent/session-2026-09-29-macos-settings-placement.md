## 3. M-20 — 설정 창 가운데 + 위치 기억

### 사고 — 설계가 한 번 뒤집혔다

처음엔 이렇게 만들었다: 화면 밖이면 **안으로 클램프**하고, 그래도 안 보이면 가운데로.

```swift
let origin = clamp(saved, ...)                                    // 항상 화면 안
return isVisible(origin, ...) ? origin : centered(...)            // 절대 실패하지 않음
```

**테스트 3건이 깨졌다.** 2인치 모니터를 분리한 상황인데 창이 `(980, 300)` 에 있었다.
클램프가 오른쪽 경계로 끌어와서 **"안 보인다 → 가운데" 분기가 한 번도 실행되지 않았다.**

> **클램프가 항상 창을 화면 안에 넣으므로, 뒤의 "보이는가" 검사는 절대 실패하지 않는다.**
> 그 검사는 죽은 코드였고, 죽은 코드는 버그를 막지 못한다.

→ 설계를 뒤집었다: **당기지 않는다. 아니면 가운데로 간다.** 판단이 하나뿐이라 검사가 값 있다.
`clamp` 를 통째로 **삭제**했다(쓰는 곳이 없어짐).

### 사고 — 주 화면 하나만 보면 멀티모니터에서 틀린다

`NSScreen.main` 만 넘기면 **왼쪽 2인치 모니터 위의 창을** "안 보인다"고 판단해
**주 화면 가운데로 튕겨 보낸다.** 그 사용자는 모니터를 그대로 두고 있는데
창만 갑자기 반대편으로 이동한다.

→ `visible: [CGRect]` 로 **화면 목록**을 받는다. **어디서든 잡히면 그 자리에 둔다.**

### 사고 — 겹침 넓이로 "보인다"고 판단하면 안 된다

맨 아래 2px 만 걸친 창을 생각해 보자. 겹침 넓이는 **460×2** 다 — 널어 보인다.
하지만 보이는 건 **창의 맨 아래 2px** 다. **제목바는 화면 반대편에 있어 끌 방법이 없다.**
사람 눈에는 "안 뜬 것"이고, 그대로 두면 "설정이 고장났다" 고 결론낸다.

→ **제목바 띠(상단 28pt)로 판정.** AppKit 좌표는 아래에서 위로라 `y + height` 가 위쪽이다.
이걸 빼먹으면 **맨 아래 띠**를 검사하게 되고, 테스트는 통과하는데
실제 화면에서 "잡을 수 있는데 안 잡힌다" 고 판단하는 조용한 오류가 된다.

## 6. 함정 기록

- `CGRect` 속성(`midX`·`intersection`·`minX`)이 안 잡히면 **`import CoreGraphics` 를 넣는다.**
  Foundation 만 쓰면 이 타입들이 AppKit 의 `NSRect` 로 해석된다.
- Swift 함수명에 **공백이 들어가면 컴파일 에러** — `test_다음_열 때_` → `test_다음에_열_때_`
- `import Foundation` 후 바로 `///` 주석이 아니라 **한 줄 비우고** 쓴다 —
  편집 도구가 주석 첫 줄을 흡수하는 일이 있었다.
- **깨진 바이트는 즉시 잡아라** — TODO 갱신 중 한글이 U+FFFD(반 대체문자)로 바뀌어
  들어갔다. `rg -c '�' docs/TODO.md` 로 잡는다. **눈에 안 띄면 그대로 커밋된다.**
