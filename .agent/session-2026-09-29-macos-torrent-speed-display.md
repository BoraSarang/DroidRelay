# 세션 로그 — 2026-09-29 (macos, M-25 토렌트 다운로드 속도 미표시)

## 1. 목표
사용자: **"토렌트에 다운로드 속도가 표시 안되네"** + 스크린샷.

## 2. 사고 — `▼104` 는 피어 수였다

스크린샷을 보면 `▲5 ▼104` 가 있다. **둘 다 시드/피어다.**
스크롤 업 줄에 있는 `▲4.6 KB/s` 는 **업 속도**고 **다운로드 속도 자리는 비어 있다.**

먼저 **서버가 값을 주는지** 확인했다. 파싱 문제가 아니라 데이터 문제일 수 있으니까.

```
/api/torrents 실측
  downloadSpeed = 102427      ← 서버는 정상적으로 주고 있었다
  uploadSpeed   = 4716
```

**서버도 파싱도 정상이었다.** 문제는 표시 로직이었다.

## 3. 원인 — `if/else` 가 업을 우선했다

```swift
if uploadBps > 0 {
    Text("▲\(upText)")            // 업이 있으면 이것만
} else {
    Text(speedText)               // 없으면 다운로드
}
```

**업 속도가 켜지는 순간 다운로드 속도가 화면에서 사라진다.**
토렌트는 시딩하면서 업이 항상 있으므로 **다운로드 중인데도 다운 속도가 안 보였다.**

잡(download) 행을 찾아보니 **같은 구조**였다. 두 곳 다 고쳤다.

> **두 값은 독립이다.** 하나가 0 이어도 다른 하나는 살아 있어야 한다.
> 조건으로 고르면 **항상 존재하는 정보를 조건에 걸어 없앤다.**

## 4. 판단 — 왜 이 앱에서 특히 위험했나

`if/else` 는 이 코드베이스에서 **대부분 옳다.** 상태가 둘 중 하나인 곳에서는 그렇다.

문제는 **그 판단이 굳어져서 값의 유무로 옮겨온 것**이다.

- **상태**는 둘 중 하나 → `if/else` 가 옳다
- **값**은 **동시에 둘 다 존재**할 수 있다 → `if/else` 가 틀린다

**상태와 값은 다르다.** 이 구분을 놓으면 아래와 같은 일이 된다:

> "다운로드 중인데 왜 속도가 안 뜨지?" → 서버에 물어보면 **값은 있다.**
> 사용자는 **"앱이 고장났다"** 고 결론. 실제로 데이터는 **화면에서만 사라졌다.**

## 5. 변경 — Core 에 순수 함수로

`if/else` 를 UI에 그대로 두면 **어떤 조합이 숨겨지는지 알 수 없다.**
`RowSpeedDisplay` 로 빼서 **9가지 조합을 전부 테스트**로 고정했다.

| down | up | 표시 |
|---|---|---|
| 102,427 | 4,716 | `▼100K` `▲5K` — **둘 다** |
| 5,000,000 | 0 | `▼5M` 만 |
| 0 | 12,000 | `▲12K` 만 (시딩) |
| 0 | 0 | **없음** |

**0 은 `nil`(빈 칸)** — "0 B/s" 를 그리는 게 아니라 **아무것도 안 그린다.**
진행 중인 다운로드 옆에 0 을 그리는 건 **노이즈**다.

## 6. 검증

- 테스트 **255 → 265건 0 실패** (신규 10건)
- 실측 `/api/torrents` — `down=65,186` `up=15,729`
- → 화면에 **`▼64K ▲16K` 둘 다 표시**

## 7. 교훈
- **"표시 안 됨" 은 데이터 문제가 아니라 렌더링 문제일 수 있다.**
  서버에 먼저 물어보면 **어디가 죽었는지**가 바로 보인다. 이번에도 그랬다.
- **`if/else` 는 상태에는 옳고 값에는 틀린다.** 이 구분을 의식하지 않으면
  "항상 존재하는 정보를 조건에 걸어 없애는" 버그가 된다.
- **같은 버그가 두 곳에 있으면 두 곳 다 고친다.** 잡 행을 안 보면
  **"토렌트만 이상하다"** 고 잘못 정리한다.
