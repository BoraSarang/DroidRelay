# 세션 로그 — 2026-10-01 (android, T-1086 로그 버그 + T-1087 속도 진단)

## 1. 질문
사용자: **"보관함 웹에서 다운로드 받는데 초당 10메가도 안나오는 이유를 알려줘"** · "**초당 얼마나 나와야 정상인지**"
→ "**직접 해봐**" → 실측으로 전환.

## 2. 결론 — 코드 결함이 아니었다
**Wi-Fi 링크 설정**이 원인이었다. 서버 코드는 한 줄도 건드리지 않았다.

| 측정 | 값 |
|---|---|
| 사용자 실제 (8GB) | 7.5 MB/s |
| curl 단일 (250MB) | 12.78 MB/s (서버측 12.98 과 일치) |
| **병렬 4개 합산** | **9.6 MB/s** ★ 단일보다 **느림** |
| 폰 라디오 `swlan0 Δtx` | 10.06 MB/s |
| Wi-Fi PHY | 144 Mbps · 802.11**n** · 2.4GHz · **20MHz** · MCS15 |

**판정 근거 3가지**: ① 병렬로 늘지 않는다(링크 포화) ② 라디오=수신속도(서버는 정상) ③ 효율 58.6%(정상 손실 아님).

## 3. ★ 비교군 오류가 진짜 함정이었다 (M-24 재발)
세션 로그(2026-09-07)의 "**서버 54.1MB/s · 맥 71MB/s, 정상 확정**"과 비교하면 **5배 회귀**처럼 보여 코드 파기 시작.
**54MB/s = 432Mbps 는 144Mbps PHY 에서 물리적으로 불가능** → 그때는 5GHz/80MHz/ac 였다.
**비교군이 다른 조건의 값이었다.** 값이 작아 보인다고 원인을 지어내지 말고 **그 값이 어떤 조건에서 나왔는지부터 본다.**

## 4. 해결 (기기 설정)
핫스팟을 5GHz/80MHz 로 → **65.1 MB/s** (PHY 1200Mbps · 효율 45.5%). 2026-09-07 기록(54~71MB/s) 범위로 복귀.
**앞으로**: 5GHz 유지 = 65MB/s / 2.4GHz 로 내려가면 10~13MB/s. 폰이 내부망(STA)과 핫스팟(AP) 동시 쓰면 단일 라디오 공유로 폭이 줄어든다.

## 5. 부수 발견 — `fmt()` MB 단위 버그 (T-1086)
MB 분기가 **GB 나눗셈**(`1_073_741_824`) → 250MB 가 `0.2MB` 로 찍힘. 진단 중 한때 헷갈린 원인.
`1_048_576` 으로 정정 + `private`→`internal` + `ServeSizeFormatTest` 6건 신규.
**수정 전 코드로 되돌리면 6건 중 3건 실패** — 버그를 실제로 잡는다(단순 통과가 아님을 확인).

## 6. 검증
| 대상 | 결과 |
|---|---|
| `ServeSizeFormatTest` | 6건 0 실패 |
| Android 전체 | 342건 중 **341 통과** |
| 실기기 로그 | `238.9MB 소요=3581ms` (수정 전 `0.2MB`) |
| 실기기 속도 | **65.1 MB/s** |
| 빌드·설치 | `R5CT215F4QK` Success · 기기 `10.38.120.211:5555` |

## 7. 함정 기록
- `adb devices` 가 비어 있어 **무선 adb 로 안 잡혔다** — 5555 는 TCP 만 받고 배너를 안 보낸다(adb 비활성). 기기에서 직접 연결 활성화 후 성공.
- `CronParserPerfTest` 실패는 **사전 존재 버그** — `git stash` 로 이번 변경을 뺀 clean tree에서도 동일 실패 확인 후 무시 (사용자 지시).
- 비교군 수치(2026-09-07 로그 "서버 54.1MB/s")는 **파일 상태로 재확인**했다. 어제 자신이 쓴 문서에 틀린 내용이 있었을 가능성도 있으므로, 과거 기록을 인용할 때는 원문을 다시 읽는다.
- Ktor `respondBytesWriter` 의 4KB 분할 가능성은 **가설로만 남겼다** — 캐시된 jar 에서 클래스 위치를 못 찾아 내부 동작을 확인하지 못했다. 검증 없이 단정하지 않는다.

## 8. 전달
