# 세션 로그 — 2026-09-29 (macos M-24 / android 뛴 값 근본 해결 시도)

## 1. 목표
사용자 지시 "그렇게 해" — M-23 에서 남긴 **"근본 해결은 Android 쪽 카운터 소스 교체"** 를 실행.

## 2. 결론부터 — **근본 해결은 불가능했다. 실측으로 확인했다.**

네 가지를 시도했고 **세 개는 실패**, 하나는 **기각**했다.

### ① `NetworkStatsManager.querySummaryForDevice` — 권한이 없다

SELinux 제한 없이 **기기 전체**를 읽는다고 보여 선택했다. 실측 결과:

```
SecurityException: Network stats history of uid -1 is forbidden for caller 10375
```

`uid -1`(전체) 조회는 **시스템 권한**이 필요했다. `PACKAGE_USAGE_STATS` grant 로도
안 되고, **시그니처에 uid 인자가 없어** 내 uid 로 바꿔 읽는 우회로도 없다.

> **javap 으로 시그니처를 미리 봤어야 했다.** `UID_ALL` 이 `Bucket` 의 **속성**이지
> 인자가 아니었다. 6개 인자로 넘겨 컴파일 에러가 나고 나서야 알았다.

### ② `/proc/net/dev` · `/sys/class/net/...` — SELinux denied (재확인)

기기에 직접 심어 확인했다. 둘 다 `Permission denied`.

### ③ 서버가 1초마다 직접 폴링 — **이게 제일 아쉬운 실패**

"클라이언트가 5초마다 물어보니까 그 사이에 정산이 끼는 거다" 는 가설이 **그럴듯**했다.
서버가 1초마다 폴링하게 만들어 실측했다:

```
폴링 주기      클라이언트가 본 최대 증분
1.00초              5,002,000 B/s
0.20초              5,002,000 B/s
0.05초              5,002,000 B/s
```

**해결되지 않았다.** 정산은 **네트워크 계층**에서 일어나 폴링 주기와 무관하다.
아무리 빨리 읽어도 두 폴링 사이에 정산이 끼면 그대로 증분으로 나타난다.

### ④ 증분 상한 — 기각

평소의 N배를 넘는 증분만 잘라 넣으면 튐은 사라진다. 그런데 **진짜 대용량 다운로드까지
잘라내며 총량까지 틀린다.** 시뮬레이션 결과:

```
폴링 1초 · 상한 4배 → 최대 증분 2,400 B/s · 총 누적 134,404 (원래 5,000,000)
```

**총량 보존이 더 중요하다** — 5 MB 를 받아야 하는데 134 KB 로 기록되면 안 된다.

## 3. 사고 — M-23 이 지우고 있던 것

조사 중 M-23 의 필터를 지속 시간별로 재실측했다. **치명적인 결함이 드러났다.**

```
지속      생존 개수  판정
 1초          0     ❌ 전부 사라짐
 3초          0     ❌ 전부 사라짐
 5초          0     ❌ 전부 사라짐
 6초          1     일부만
10초          5     일부만
```

> **3초짜리 실제 다운로드를 전부 지우고 있었다.**

M-23 의 테스트는 **10초 지속**만 봤다. **3초·5초는 안 봤다.** 그래서
"지속 전송은 살아남는다" 는 계약이 **사실과 달랐는데 테스트가 통과**했다.

> **계약을 테스트가 지킨다고 믿지 말고, 계약이 무엇인지 다시 물어봐야 한다.**
> "10초는 살아남는다" 와 "3초도 살아남는다" 는 다른 계약이다. **짧은 쪽을 안 물어봤다.**

## 4. 결론 — 지우지 않고 구분한다

사용자 결정: **원본 유지 + 축에 참고값 병기**.

```
이전 : 5.3 MB/s
이후 : 4.8 MB/s · 보통 2 KB/s
```

- **숨기지 않는다** — 스파이크가 있었다는 사실을 지우면 **그래프가 고장 난 걸로** 읽는다
- **비슷하면 붙이지 않는다** — `"1.2 MB/s · 보통 1.1 MB/s"` 는 **같은 말을 두 번 하는 것**
- 계산은 Core 의 순수 함수 `SpeedScale.axisLabel` — **OS 없이 검증된다**

실패한 3건 + 기각한 1건을 **`NetSpeedRoutes.kt` 주석에 남겼다.** 다음에 누가
같은 시도를 하면 그때 읽게.

## 5. 실기기 검증

- 릴리즈 APK 는 서명 불일치(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`) — 기기에 debug 본이 있음
- **사용자 선택: debug 빌드로 설치** (데이터 보존)
- 설치 후 `/api/net/speed` → **`supported: false`** — 실험 빌드가 동작 중
- **원본으로 되돌린 뒤 재설치** → `supported: true` 복구 확인

**기기에 남은 변화 없음** (debug 서명본, 데이터 보존).

## 6. 사고 — 조용한 실패가 두 번

**첫째**: `runCatching` 이 `SecurityException` 을 삼켜서 원인이 안 보였다.
`supported: false` 만 보고 "권한 없나?" 하고 한참을 헤맸다. → **`onFailure` 로 로그를 남겼다.**

**둘째**: `NetSpeedCounterTest` 가 **"서버 1초 폴링이면 해결된다"** 는 제 가설을
정확히 실패로 잡아냈다:

```
정상을_흡수해도_총량이_보존된다 FAILED
  expected:<5000000> but was:<5004000>
```

**테스트가 가설을 죽였다.** 그게 테스트의 존재 이유다.

## 7. 함정 기록
- `javap` 출력의 **상수 목록과 함수 시그니처는 다르다.** `UID_ALL` 이 보여도
  인자가 아닐 수 있다. **컴파일 에러로 확인하는 게 빠르다.**
- `intArrayOf(...).mapNotNull` → `toList()` 가 먼저 필요하다
- Android 테스트는 **루트 패키지**(`com.borasarang.droidrelay`)에 둔다 — `.relay` 아님
- JUnit `assertEquals` 는 **3인자(메시지) 오버로드가 없다** → `assertEquals(msg, a, b)` 로
  **메시지가 첫 인자**다. `assertTrue(condition, msg)` 도 **msg 가 첫 인자**다
- 역따옴표 테스트명에 공백이 들어가면 `fun \`이름() {` 로 깨진다
