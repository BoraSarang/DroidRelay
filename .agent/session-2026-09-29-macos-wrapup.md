## 5. 이번 하루의 교훈 (가장 값졌던 것)

### ① 계산이 맞다는 것과 표시가 맞는다는 것은 다르다

M-21(설정창)이 대표적이었다. `WindowPlacement.resolve` 는 (670, 291) 을 정확히 냈고
테스트도 100% 통과했는데 **실제 창은 (0, -28) 에 있었다.**

> **계산이 맞다 ≠ 창이 그곳에 간다.**
> 순수 함수를 테스트로 완전히 고정해도, **그 값을 적용하는 코드가 틀리면 아무 도움이 없다.**

→ 이 프로젝트는 Core/UI 분리로 계산 로직을 테스트해 왔는데, 정작 **그 계산이 창에
들어가는 지점**이 비어 있었다. **진단은 실제 대상을 조작하고 그 상태를 읽어야 한다.**

### ② "해결했다" 고 기록하기 전에 실패를 확인한다

M-24 는 근본 해결을 시도했다가 **세 가지가 전부 막혔다**:

| 시도 | 결과 |
|---|---|
| `NetworkStatsManager` | `SecurityException: uid -1 is forbidden` — 권한 필요 |
| `/proc/net/dev` · `/sys/class/net` | SELinux denied |
| 서버 1초 폴링 | 0.05초로도 5 MB/s 그대로 — **정산은 네트워크 계층이라 무관** |

**실패한 경로를 코드 주석에 남겼다** — 다음에 누가 같은 시도를 하면 그때 읽게.

### ③ M-23 이 지우고 있던 것을 나중에 발견했다

M-24 를 조사하다가 M-23 의 필터를 지속 시간별로 재실측했다.
**1~5초짜리 실제 다운로드를 전부 지우고 있었다.** 테스트가 10초만 봤으니까 통과한 거다.

> **계약을 테스트가 지킨다고 믿지 말고, 계약이 무엇인지 다시 물어봐야 한다.**
> "10초는 살아남는다" 와 "3초도 살아남는다" 는 다른 계약이다.

### ④ `if/else` 는 상태에는 옳고 값에는 틀린다

M-25 의 근본 원인. 토렌트는 시딩하면서 업이 항상 켜져 있어서 **다운로드 중인데도
다운로드 속도가 안 보였다.** 잡 행도 같은 구조였다.

> 조건으로 고르면 **항상 존재하는 정보를 조건에 걸어 없앤다.**

### ⑤ 조용한 실패가 두 번 있었다

- `runCatching` 이 `SecurityException` 을 삼켜서 원인이 안 보임 → `onFailure` 로그 추가
- `--settings-check` 가 **계산값만** 찍고 실제 창 좌표를 안 읽음

**이 프로젝트에서 조용한 실패가 가장 경계되는 종류**다. 오늘 두 번 다 만났다.
