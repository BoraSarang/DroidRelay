## 2. 온도 제거 (PR #36, 병합 `229a591`)

목업 `docs/mockups/mac-menubar.html` 의 통계 행 3칸 중 "온도" 를 제거했다.

제거한 3곳: HTML `<div>온도<b id="stTemp">` · `state.temp: 38` · `$('#stTemp').textContent`

**왜**: 서버에 엔드포인트가 없다. `/api/info` 실측 = version·storageFree·storageTotal·
ip·port·running·speedTotalBps·httpsEnabled·httpsPort. **온도 필드가 없다.**

> **값이 없는 칸은 "—" 가 영영 보인다.** 정보를 더하는 게 아니라 **없는 자리를 그리는 것**이다.
> (M-16 의 "받기는 모든 파일에" 와 같은 결론)

HTML 에 제거 사유 주석을 남겼다 — 다음에 누가 3칸으로 되돌리면 이유를 알 수 있게.
CSS 는 `flex:1` 이라 칸 수와 무관. 검증: 칸 2개 / id 2개 / 스크립트 참조 2개 — 누락 없음.

**Android 웹 가드의 온도·배터리는 별개라 건드리지 않았다.** (`/api/guard/status` 로 동작 중)

## 3. M-23 — 그래프 5.3 MB/s (PR #37)

### 사고 — 계산이 아니라 나눈 대상이 문제였다

스크린샷의 모순을 먼저 짚었다: 라벨은 `기기 ↓4K ↑17K` 인데 **축은 5.3 MB/s**.
스파이크가 축에 닿지 않는다. → **라벨과 축이 다른 값을 말한다.**

`SpeedFormat` · `DeviceTrafficRate` · `SpeedHistory.push` 를 읽었다. **나눗셈은 정확했다.**

`/api/net/speed` 를 20회 1초 간격으로 실측했다:

```
정상 구간   1 ~ 5 KB/s        ← 실제 트래픽
보충 구간   2 ~ 5 MB/s        ← 1000배 튀었다가 바로 내려옴
```

`TrafficStats.getTotalTxBytes()` 는 **유휴 상태가 풀리면서 누락된 누적량을 한 번에 보충**한다.

> **계산은 정확했다. 나눈 대상이 보충분이었다.**

### 판단 3가지

**① 중앙값을 쓴다 — 평균은 못 쓴다**

평균은 **스파이크 하나에 함께 끌려간다.** 기준이 평균이면 이상치가 기준을 올리고,
그러면 **그 다음 이상치는 "정상" 이 된다.** 중앙값은 소수 구간이 휘둘리지 않는다.

```
[10, 10, 10, 5_000_000]  →  평균 125만(기준 망가짐) · 중앙값 10(안전)
```

**② 기준이 0 이면 판정하지 않는다 — 가장 위험한 자리**

"0 보다 큰 모든 것" 을 걸으면 **트래픽이 없는 구간에서 시작하는 모든 실제 전송을 버린다.**
조용히 지워진 데이터가 된다.

**③ 지속 전송은 살아남는다 — 이게 실패하는 방향**

실전 다운로드는 수 초 안에 여러 샘플이 쌓여 **기준이 올라간다.** 그래서
첫 프레임만 걸리고 이후는 통과한다. **이게 잘못되면 실제 트래픽을 숨기게 되므로
테스트로 고정했다** — `test_다운로드_중반은_확실히_살아남는다`.

`baselineWindow=10` · `spikeRatio=50` — 실측 비율이 1000배니 50배면 넉넉하다.

### 사고 — 4곳 전부 같은 값을 써야 한다

처음엔 그래프만 걸었다. 그런데 그러면 **라벨은 `17K` 인데 축만 `5.3 MB/s`** 인
**사용자가 본 그 모순이 그대로 남는다.** 같은 화면에서 두 개가 다른 말을 하게 된다.

→ **그래프 · 축(`peak`) · 메뉴바 · 범례 4곳 전부** 같은 필터를 태웠다.

메뉴바가 특히 놓치기 쉬웠다. `updateBadge()` 가 원본 `deviceSpeed` 를 쓰고 있어서
스파이크 순간 `↑5M` 이 떴다. `displayDeviceSpeed` 를 새로 exposing 했다.

**원본은 남겨둔다** — 데이터를 지우는 게 아니라 **보여주는 값을 고르는 것**이라
나중에 "실제 몇 바이트냐" 를 물으면 답할 수 있다.

## 5. 교훈
- **계산이 맞다는 것과 표시가 맞는다는 것은 다르다.** 나눗셈을 검증하고
  테스트로 고정했는데 **입력값 자체가 보충분**이었다. 입력이 무엇인지 봐야 한다.
- **표시 필터를 한 곳에만 걸면 그 자리에서 고장이다.** 원인이 아니라 **증상**을 고친 것.
  화면에 값이 몇 군데 있는지 먼저 세고 **전부** 태워야 한다.
- **"0 은 기준이 아니다" 를 명시해야 한다.** 0 을 기준으로 잡는 게 가장 자연스러워 보이지만
  **트래픽이 없는 구간에서 시작하는 실제 전송을 전부 지운다.** 조용히 사라지는 게 제일 나쁘다.
