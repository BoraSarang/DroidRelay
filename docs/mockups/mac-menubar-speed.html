설정 — 팝오버 하단

그래프도 같은 설정을 따른다. 꺼진 출처의 계열은 그래프에서도 사라진다 — 메뉴바에서 안 보이는데 그래프에만 있으면 "이건 뭐지"가 된다.
기기 계��은 신규 서버 엔드포인트가 있어야 나온다. 현재 DroidRelay 서버에 기기 전체 카운터를 읽는 코드가 없다 (/api/info 의 speedTotalBps 는 HTTP 잡 다운로드 합이라 토렌트·업로드 미포함 — 값이 0 인 이유). 서버 작업이 선행되어야 이 스위치를 켤 수 있다. 켜려고 시도하면 **앱이 아니라 폰 쪽에서** 권한·파싱 실패가 나므로, 스위치는 엔드포인트가 생기고 나서 활성화하는 게 맞다.

그래프 — 4계열 (활성화된 출처만)

공유 축 추천

4계열이 같은 Y축. 출처 간 크기 비교가 된다

계열별 정규화 RelayConsole 현재

계열마다 자기 min/max 로 拉伸. 형상은 보이지만 크기 비교가 안 된다

Droid 는 기기의 부분집합이라 같은 축에 놓아야 "나머지 트래픽은 무엇이 쓰나"가 읽힌다. 계열별 정규화를 쓰면 작은 쪽이 최대 높이까지 부풀려 몇 배인지 읽을 수 없다 — 첨부 이미지의 그래프가 산 모양인 이유가 이것이다.
밀도 주의 — 서버는 상태가 바뀔 때만 tick 을 보낸다(15초 beat 외엔 조용). 그걸로 그리면 평소엔 직선이다. 촘촘한 곡선을 얻으려면 클라이언트가 1초 주기로 값을 뽑아 자체 히스토리를 쌓아야 — 서버를 1초마다 때리지 말고, 이미 있는 10초 백업 폴링을 그래프용 샘플러로 좁힌다.
